# API reference

This reference follows the FastAPI routes and Pydantic request models in `app/routes/` and `app/schemas.py`. Successful JSON API calls below return HTTP 200 unless stated otherwise; `/docs` returns the Swagger UI page. Protected calls use `Authorization: Bearer <access-token>`. The Swagger UI at `/docs` and OpenAPI schema at `/openapi.json` are generated by FastAPI.

Start the server at `http://127.0.0.1:8000`. The examples use shell variables so they can be copied as a flow:

```bash
export BASE=http://127.0.0.1:8000
export SUBJECT=mathematics
export USERNAME='<disposable-username>'
export PASSWORD='<private-password-for-local-testing>'
```

Registration and login return access/refresh tokens. Keep tokens private and do not paste real tokens in tickets or docs.
Set `TOKEN`, `REFRESH_TOKEN`, and `TEACHER_TOKEN` from the responses as you follow the examples.

## Health and documentation

| Method and path | Auth | Request | Success response | Errors |
|---|---|---|---|---|
| `GET /health` | No | None | `{"status":"ok"}` | None expected. |
| `GET /ready` | No | None | `{"status":"ready","database":"ok","recommender_mode":"hybrid"}`; mode may be `zpd-fallback`. | `503` if database/readiness check fails. |
| `GET /docs` | No | None | FastAPI Swagger UI page. | None expected. |
| `GET /openapi.json` | No | None | OpenAPI JSON generated from registered routes and schemas. | None expected. |

```bash
curl -i "$BASE/health"
curl -i "$BASE/ready"
```

The UI is served at `/`. Static assets are under `/static/`.

## Authentication and account

### `POST /api/auth/register`

No auth. Body: `username` (3–32 ASCII letters, digits, underscores), `password` (at least 10 characters, not all digits or a small known-common list, at most 72 UTF-8 bytes), and optional `role` (`student` by default or `teacher`). New users have no pre-enrolled subjects; students complete profile setup and choose subjects during onboarding.

Success body: `{"token":"...","refresh_token":"...","username":"...","role":"student"}`.
Errors: `409` if registration collides with an existing database constraint; `422` invalid body/role/password; `429` rate limit.

```bash
curl -i -X POST "$BASE/api/auth/register" -H 'Content-Type: application/json' \
  -d "{\"username\":\"$USERNAME\",\"password\":\"$PASSWORD\",\"role\":\"student\"}"
```

To create a teacher for local testing, use a different disposable username and password. Public teacher self-registration is a known security limitation.

```bash
curl -i -X POST "$BASE/api/auth/register" -H 'Content-Type: application/json' \
  -d "{\"username\":\"$TEACHER_USERNAME\",\"password\":\"$TEACHER_PASSWORD\",\"role\":\"teacher\"}"
```

### `POST /api/auth/login`

No auth. Body: `username`, `password`. Success body is the same token object as registration. Errors: `401` invalid credentials; `422` invalid username/body; `429` rate limit.

```bash
curl -i -X POST "$BASE/api/auth/login" -H 'Content-Type: application/json' \
  -d "{\"username\":\"$USERNAME\",\"password\":\"$PASSWORD\"}"
```

### `POST /api/auth/refresh`

No access-token auth. Body: `{"refresh_token":"<refresh-token>"}`. Success body is a new token object; the previous refresh token is revoked. Errors: `401` invalid, expired, revoked, or orphaned refresh token; `422` invalid body.

```bash
curl -i -X POST "$BASE/api/auth/refresh" -H 'Content-Type: application/json' \
  -d "{\"refresh_token\":\"$REFRESH_TOKEN\"}"
```

### `POST /api/auth/logout`

No access-token auth. Body: `{"refresh_token":"<refresh-token>"}`. Success body: `{"status":"logged out"}`. A well-formed unknown token is treated idempotently; invalid JSON/body gets `422`.

```bash
curl -i -X POST "$BASE/api/auth/logout" -H 'Content-Type: application/json' \
  -d "{\"refresh_token\":\"$REFRESH_TOKEN\"}"
```

### `DELETE /api/account`

Access token required. Body: `{"password":"<current-password>"}`. Deletes learner-owned manual/discovered subject paths, citations, enrollment/reference metadata, progress, interactions, and tokens as well as the account. Shared content packs are retained. Success body: `{"status":"account and associated data deleted"}`. Errors: `401` invalid access token or password confirmation; `422` invalid body; `429` rate limit.

```bash
curl -i -X DELETE "$BASE/api/account" -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d "{\"password\":\"$PASSWORD\"}"
```

## Learner onboarding and profile

New student accounts must complete onboarding before using learner-state, subject, quiz, history, or recommendation routes. Profile endpoints and account deletion remain available while onboarding is incomplete. Teachers do not have learner profiles. The app does not ask for age or date of birth.

### `GET /api/onboarding/options`

No auth. Returns country, curriculum, education level, institution type, language, goal, style, and experience choices loaded from `content/learner-profile/options.json`. This data file can be extended without changing application code.

```bash
curl -i "$BASE/api/onboarding/options"
```

### `GET /api/me/profile`

Access token required. Returns `{"required":true,"completed":false,"profile":null}` for a student who has not completed onboarding, or the saved profile. Teacher accounts receive `{"required":false,"completed":true,"profile":null}`.

```bash
curl -i "$BASE/api/me/profile" -H "Authorization: Bearer $TOKEN"
```

### `PUT /api/me/profile`

Access token required. Body contains `country`, `language`, `education_level`, `institution_type`, `grade_year`, optional `curriculum_program`, `field_of_study`, `learning_goal`, `weekly_time_hours` (0.5–80), `learning_style`, `prior_experience`, and `consent:true`. Values must match the current options data. A saved profile initializes or updates every enrolled subject's level and goal. Success returns `{"required":true,"completed":true,"profile":{...}}`; errors include `401` unauthorized, `403` non-student account, and `422` invalid fields, unrecognized choices, or missing consent.

```bash
curl -i -X PUT "$BASE/api/me/profile" -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"country":"IN","language":"English","education_level":"high_school","institution_type":"school","grade_year":"Grade 10","curriculum_program":"CBSE","field_of_study":"Science","learning_goal":"exam","weekly_time_hours":5,"learning_style":"examples","prior_experience":"some","consent":true}'
```

### `DELETE /api/me/profile`

Access token required. Deletes the profile and resets per-subject level/goal to the neutral defaults. The student must complete onboarding again before learner routes can be used. Success: `{"status":"profile deleted","onboarding_required":true}`. Errors include `401` unauthorized and `403` non-student account.

```bash
curl -i -X DELETE "$BASE/api/me/profile" -H "Authorization: Bearer $TOKEN"
```

Until a student profile exists, learner endpoints return HTTP `409` with `Complete learner onboarding before continuing`. Account deletion remains available and removes the profile with the rest of the account data.

## Subjects and learner state

### `GET /api/subjects`

No auth. No body. Returns every valid regular pack, whether or not it is installed. Sample packs under `content/examples/` are excluded unless `include_samples=true`; invalid pack folders are returned in `errors` and logged on the server. Each entry includes `installed:true|false`. Example: `{"subjects":[{"id":"python-programming","name":"Python Programming","description":"...","topic_count":6,"questions_status":"draft; teacher review required","source":"pack","status":"draft","installed":false}],"errors":[]}`.

```bash
curl -i "$BASE/api/subjects"
curl -i "$BASE/api/subjects?include_samples=true"
```

### `GET /api/me/subjects`

Access token required. No body. Success includes enrollment metadata such as source/status, topic count, target depth, education level used, and any reference book: `{"active_subject_id":null,"subjects":[]}` for a new student who has not chosen subjects.
Errors: `401` missing/invalid/expired access token.

```bash
curl -i "$BASE/api/me/subjects" -H "Authorization: Bearer $TOKEN"
```

### `POST /api/subjects/{subject_id}/enroll`

Access token required. Optional body: `{"target_depth":"beginner"}`; allowed depths are `beginner`, `intermediate`, and `advanced`. Creates enrollment and initial subject state if absent, and makes it active. Each learner may have at most eight active enrollments. Success: `{"status":"enrolled","subject_id":"physics","diagnostic_required":true}`.
Errors: `401` unauthorized; `404` unknown or another learner's private subject; `409` when the learner already has eight active enrollments.

### `POST /api/subjects/{subject_id}/install`

Access token required. Imports the named valid regular or sample pack idempotently, then enrolls and activates it for the learner. Sample subjects are normally exposed by the UI's explicit sample option. Body is optional: `{"target_depth":"beginner"}`. Errors: `401` unauthorized; `404` pack not found; `409` enrollment limit or conflicting non-pack subject; `422` pack validation failure.

```bash
curl -i -X POST "$BASE/api/subjects/python-programming/install" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"target_depth":"beginner"}'
```

### `DELETE /api/subjects/{subject_id}/enroll`

Access token required. No body. Removes the enrollment. Existing state and history are retained. If the removed subject was active, another enrollment becomes active or the active subject is cleared. Success: `{"status":"unenrolled","subject_id":"physics"}`.
Errors: `401` unauthorized; `404` not enrolled.

```bash
curl -i -X DELETE "$BASE/api/subjects/$SUBJECT/enroll" -H "Authorization: Bearer $TOKEN"
```

### `PUT /api/me/subject`

Access token required. Body: `{"subject_id":"physics"}` (1–80 characters). Success: `{"active_subject_id":"physics"}`.
Errors: `401` unauthorized; `403` not enrolled; `422` invalid body.

```bash
curl -i -X PUT "$BASE/api/me/subject" -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d "{\"subject_id\":\"$SUBJECT\"}"
```

### `GET /api/subjects/{subject_id}/progress`

Access token required. No body. After onboarding, success has `subject_id`, `diagnostic_completed`, `n_interactions`, `total_time_min`, `engagement_ma`, `last_score`, `learner_level` (0–100), `learner_level_label`, `learning_goal`, and `topics`. Each topic has `id`, `name`, `order`, `mastery` (0–1 estimate), `attempts`, `prerequisites`, and `prerequisites_met`.
Errors: `401` unauthorized; `403` not enrolled; `404` unknown subject.

```bash
curl -i "$BASE/api/subjects/$SUBJECT/progress" -H "Authorization: Bearer $TOKEN"
```

### `GET /api/subjects/{subject_id}/diagnostic`

Access token required. No body. On first call, creates and persists a diagnostic session, lazily building quality-checked question banks from saved, cited Wikipedia/Wikidata material. It returns available questions, `session_id`, and question `id`, `options`, and topic metadata; correct answers are never returned. Topics without at least five accepted questions are marked limited and skipped, not replaced with a self-rating prompt.
Errors: `401` unauthorized; `403` not enrolled; `404` unknown subject.

```bash
curl -i "$BASE/api/subjects/$SUBJECT/diagnostic" -H "Authorization: Bearer $TOKEN"
```

### `POST /api/subjects/{subject_id}/diagnostic`

Access token required. Body: `{"session_id":"<session-id>","answers":{"question-id-1":0}}`. Answer IDs must exactly match the available questions delivered for that session. Limited topics are skipped. Success returns graded feedback with correct answers and source sentences/links, `score_source:"graded quiz answers only"`, and progress.
Errors: `401` unauthorized; `403` not enrolled; `404` unknown subject; `409` already completed; `422` wrong question IDs, invalid option, or invalid body.

```bash
curl -i -X POST "$BASE/api/subjects/$SUBJECT/diagnostic" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"session_id":"<session-id-from-diagnostic-get>","answers":{"mathematics.algebra.diagnostic":0,"mathematics.geometry.diagnostic":1}}'
```

The example question IDs are illustrative; use the IDs returned by the diagnostic GET request.

### `GET /api/subjects/{subject_id}/improvement`

Access token required. Returns only real learner-specific weakness signals: topics with low mastery or a self-rating of 3/5 or lower, attempts, actual quiz score trend, prerequisite names, and available cited resources. It does not estimate missing scores. With no weakness data it returns an empty `topics` list and a message.

### `POST /api/subjects/{subject_id}/topics/{topic_id}/rating`

Access token required. Body: `{"rating":0}` through `{"rating":5}`. Saves a self-reported weak signal, not a quiz score. The topic must belong to the enrolled subject. Topics with no usable question bank remain eligible for self-rating.

### Subject discovery

All discovery endpoints require an access token. Provider text is untrusted and should be rendered as text, not HTML.

- `GET /api/discovery/search?q=...&level=...` searches public providers and returns candidates with `name`, a summary under 300 characters, source name, source URL, and confidence. `level` is optional and defaults to the saved education level.
- `GET /api/discovery/books?q=...` searches Open Library. Results contain title, authors, edition, publisher, year, ISBNs, and a record link; book text is not copied.
- `GET /api/discovery/preview?name=...&source_url=...&level=...` returns an ordered topic-path preview with levels.
- `POST /api/discovery/subjects` creates an unreviewed draft subject from an approved public source. Body: `{"name":"Astronomy","source_url":"https://en.wikipedia.org/wiki/Astronomy","target_depth":"beginner"}`. To enrich an owned empty manual subject, include its `manual_subject_id`. The source and retrieval time are attached to subject/topic/resource rows; saved short extracts support lazy rule-based question generation.
- `POST /api/subjects/manual` creates and enrolls an owned manual subject from `{"name":"My subject"}`, then searches public providers and builds a cited draft path when available. The response includes `path_status` (`built`, `offline`, or `not_found`), `topic_count`, and a learner-readable `message`. Generated questions remain lazy and are prepared when a topic is opened. If no path is found, the subject remains enrolled with an explanation and retry/result-selection options in the dashboard.
- `POST /api/subjects/{subject_id}/build-path` retries discovery for an enrolled, owned manual subject with no topics. It returns the same `path_status`, `topic_count`, and `message` fields as manual-subject creation. Owned manual/discovered subjects are included in `GET /api/me/subjects` and count toward the eight-subject cap.
- `PUT /api/subjects/{subject_id}/reference` attaches a book's short metadata and HTTPS link to an existing enrollment.

Discovery returns clear no-result/offline messages. Search is rate-limited per user in process memory; the server restricts fetches to approved HTTPS hosts, rejects private DNS results, disables redirects and environment proxies, caps responses, and applies timeouts and a short response cache. These protections and limits are local single-process controls, not deployment-grade distributed controls. Enrollment is capped at eight active subjects per user; unenrolling frees a slot.

### `GET /api/subjects/{subject_id}/recommendations?top_k=5`

Access token required. No body. `top_k` is 1–20, default 5. Success: `{"subject_id":"mathematics","recommendations":[{"action":"<resource-id>","resource_id":"<resource-id>","topic_id":"...","topic":"...","resource_type":"article","title":"...","difficulty":2.0,"duration_min":18.0,"utility":0.72,"explanation":{"predicted_score":62.0,"difficulty_fit":0.81,"engagement":0.55,"prerequisites_met":true,"coverage":0.34}}]}`. Some fields/values vary by model mode. Only prerequisite-eligible resources backed by a usable source-generated question bank are returned. When all topics are limited, the response includes a `message` explaining that those topics were skipped.
Errors: `401` unauthorized; `403` not enrolled; `404` unknown subject; `409` diagnostic not completed; `422` invalid `top_k`.

```bash
curl -i "$BASE/api/subjects/$SUBJECT/recommendations?top_k=5" \
  -H "Authorization: Bearer $TOKEN"
```

## Quiz and history

### `GET /api/subjects/{subject_id}/resources/{resource_id}/quiz`

Access token required. Lazily prepares questions from saved cited Wikipedia/Wikidata material, opens an activity session, and returns one public question with `session_id`, options, difficulty, review status, attribution, and source URL. The correct option and explanation remain server-side until grading. A bank with fewer than five questions is marked limited. If no usable questions pass source and quality checks, HTTP 200 returns `questions:[]`, `session_id:null`, `limited:true`, and an explanatory message; self-rating is not the main learning path.
Errors: `401` unauthorized; `403` not enrolled; `404` unknown subject/resource; `409` diagnostic not complete.

```bash
curl -i "$BASE/api/subjects/$SUBJECT/resources/$RESOURCE_ID/quiz" \
  -H "Authorization: Bearer $TOKEN"
```

### `POST /api/subjects/{subject_id}/resources/{resource_id}/submit`

Deprecated. Adaptive quiz grading uses `POST /api/subjects/{subject_id}/quiz-sessions/{session_id}/answer` instead. The legacy resource submit endpoint now responds HTTP 409.
Errors: `409` this legacy route has been replaced by adaptive quiz sessions.

```bash
curl -i -X POST "$BASE/api/subjects/$SUBJECT/resources/$RESOURCE_ID/submit" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"answers":[0,1,0],"duration":8.5}'
```

This legacy route returns HTTP 409 and directs clients to use the adaptive session endpoint below.

### `POST /api/subjects/{subject_id}/quiz-sessions/{session_id}/answer`

Access token required. Body: `{"question_id":"<shown-question-id>","answer":0,"duration":1.5}`. `answer` is a zero-based option index. The response grades the shown question, updates mastery only from that answer, returns the correct answer and cited source sentence/link, weak topics and improvement hints, then supplies the next unseen question or marks the session complete. Questions do not repeat within a session. Earlier questions may be reused after unseen questions are exhausted, and the response reports reuse. Sessions are learner-isolated.
Errors: `401` unauthorized; `404` session does not belong to this learner or subject; `409` inactive session or question already answered/not exposed; `422` answer index or duration is invalid.

Learners may report a shown question with `POST /api/subjects/{subject_id}/questions/{question_id}/report`, sending `{"reason":"ambiguous","details":"Optional note"}`. Teachers list reports through `GET /api/teacher/question-reports` and review them through `PATCH /api/teacher/question-reports/{report_id}`.

### `GET /api/subjects/{subject_id}/history?limit=20`

Access token required. No body. `limit` is 1–200, default 20. Success: `{"history":[{"id":1,"topic":"...","resource_id":"...","resource_type":"quiz","difficulty":2.0,"duration":8.5,"score":66.67,"gain":0.12,"engagement":0.6,"timestamp":"..."}]}`.
Errors: `401` unauthorized; `403` not enrolled; `404` unknown subject; `422` invalid `limit`.

```bash
curl -i "$BASE/api/subjects/$SUBJECT/history?limit=20" \
  -H "Authorization: Bearer $TOKEN"
```

## Teacher content endpoints

All teacher endpoints require an access token for a `teacher` role. Because public self-registration can currently request `role:"teacher"`, this is a role gate, not a secure teacher provisioning system. IDs are generated by prefixing the parent topic/subject ID.

### `POST /api/teacher/subjects/{subject_id}/topics`

Body: `{"slug":"vectors","name":"Vectors","order":7,"prerequisites":["linear-algebra"]}`. `slug` is lowercase letters/digits/hyphens, max 80; name max 160; order is at least 1; prerequisites are optional topic slugs/IDs in the same subject. Success: `{"id":"mathematics.vectors","name":"Vectors","subject_id":"mathematics"}`.
Errors: `401` unauthorized; `403` student role; `404` subject not found; `409` duplicate topic; `422` invalid fields, cross-subject/unknown/duplicate/self prerequisite, or cycle.

```bash
curl -i -X POST "$BASE/api/teacher/subjects/$SUBJECT/topics" \
  -H "Authorization: Bearer $TEACHER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"slug":"vectors","name":"Vectors","order":7,"prerequisites":[]}'
```

### `PATCH /api/teacher/topics/{topic_id}`

Body may include `name`, `order`, and/or a complete replacement `prerequisites` list. Success: `{"id":"mathematics.vectors","name":"Vectors","order":7}`.
Errors: `401` unauthorized; `403` student role; `404` topic not found; `422` invalid fields or prerequisite graph.

```bash
curl -i -X PATCH "$BASE/api/teacher/topics/$TOPIC_ID" \
  -H "Authorization: Bearer $TEACHER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Vectors and Spaces","order":7,"prerequisites":["linear-algebra"]}'
```

### `POST /api/teacher/topics/{topic_id}/resources`

Body: `{"id":"practice","type":"interactive","title":"Vector practice","difficulty":2.5,"duration":15,"body":"Draft practice activity."}`. Type is one of `video`, `article`, `quiz`, `interactive`, `project`; difficulty is 1–5; duration is greater than 0 and at most 600; a non-empty `url` or `body` is required. Success: `{"id":"mathematics.vectors.practice","topic_id":"mathematics.vectors"}`.
Errors: `401` unauthorized; `403` student role; `404` topic not found; `409` duplicate resource; `422` invalid fields/content.

```bash
curl -i -X POST "$BASE/api/teacher/topics/$TOPIC_ID/resources" \
  -H "Authorization: Bearer $TEACHER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"id":"practice","type":"interactive","title":"Vector practice","difficulty":2.5,"duration":15,"body":"Draft practice activity."}'
```

### `PATCH /api/teacher/resources/{resource_id}`

Body may include `type`, `title`, `difficulty`, `duration`, `url`, and/or `body`. A non-empty URL or body must remain after the update. Success: `{"id":"...","topic_id":"..."}`.
Errors: `401` unauthorized; `403` student role; `404` resource not found; `422` invalid fields or resource without URL/body.

```bash
curl -i -X PATCH "$BASE/api/teacher/resources/$RESOURCE_ID" \
  -H "Authorization: Bearer $TEACHER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"title":"Updated vector activity","difficulty":2.8}'
```

### `POST /api/teacher/topics/{topic_id}/questions`

Body: `{"id":"practice-1","difficulty":2.5,"text":"Which vector has length one?","options":["[1,0]","[2,0]"],"correct_option":0,"explanation":"The first vector has length one.","diagnostic":false}`. There must be 2–8 non-empty options; `correct_option` must point to one. Success: `{"id":"mathematics.vectors.practice-1","topic_id":"mathematics.vectors"}`.
Errors: `401` unauthorized; `403` student role; `404` topic not found; `409` duplicate question or a second diagnostic question for the topic; `422` invalid fields.

```bash
curl -i -X POST "$BASE/api/teacher/topics/$TOPIC_ID/questions" \
  -H "Authorization: Bearer $TEACHER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"id":"practice-1","difficulty":2.5,"text":"Which vector has length one?","options":["[1,0]","[2,0]"],"correct_option":0,"explanation":"The first vector has length one.","diagnostic":false}'
```

### `PATCH /api/teacher/questions/{question_id}`

Body may include `difficulty`, `text`, `options`, `correct_option`, `explanation`, `diagnostic`, and `status:"approved"`. Approval marks the item teacher-reviewed; it does not independently verify its source. Success: `{"id":"...","topic_id":"..."}`.
Errors: `401` unauthorized; `403` student role; `404` question not found; `409` a second diagnostic question would be created; `422` invalid fields or answer index/options.

```bash
curl -i -X PATCH "$BASE/api/teacher/questions/$QUESTION_ID" \
  -H "Authorization: Bearer $TEACHER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"difficulty":3,"explanation":"Updated explanation."}'
```

`DELETE /api/teacher/questions/{question_id}` deletes a question and its associated exposures/reports. Teachers can list question reports with `GET /api/teacher/question-reports?status=open` and review one with `PATCH /api/teacher/question-reports/{report_id}` using `{"status":"reviewed"}` or `{"status":"dismissed"}`.

## Compatibility endpoints

These routes operate on the authenticated learner's active subject. New clients should use the explicit subject routes above.

### `GET /api/meta`

No auth. Success: `{"recommender_mode":"hybrid"}` or `{"recommender_mode":"zpd-fallback"}`.

```bash
curl -i "$BASE/api/meta"
```

### `GET /api/me/state`

Access token required. Success includes `subject_id`, ability/motivation estimates, mastery and attempts arrays, topic-keyed mastery map, recent scores, total time, engagement average, last difficulty/score, and interaction count. Errors: `401` unauthorized; `409` no active subject pack.

```bash
curl -i "$BASE/api/me/state" -H "Authorization: Bearer $TOKEN"
```

### `GET /api/recommend?top_k=5`

Access token required. `top_k` is 1–20. Success: `{"subject_id":"mathematics","recommendations":[...legacy recommendation objects with numeric action index...]}`. Errors: `401` unauthorized; `409` no active subject pack; `422` invalid `top_k`.

```bash
curl -i "$BASE/api/recommend?top_k=5" -H "Authorization: Bearer $TOKEN"
```

### `GET /api/quiz/{action}`

Access token required. `action` is an active-catalog integer index. Success: `{"action":0,"resource_id":"...","topic":"...","questions":[{"id":"...","question":"...","options":["..."],"difficulty":2}]}`. Errors: `401` unauthorized; `400` invalid action; `409` no active subject; no answer keys are returned.

```bash
curl -i "$BASE/api/quiz/0" -H "Authorization: Bearer $TOKEN"
```

### `GET /api/catalog`

No auth. No body. Lists the imported Mathematics resources with numeric action, ID, topic, type, title, difficulty, and duration. If Mathematics is not imported, returns an empty catalogue.

```bash
curl -i "$BASE/api/catalog"
```

### `POST /api/interaction`

Access token required. Body: `{"action":0,"answers":[0,1,0],"duration":8.5}`. `action` must be an active-catalog index; answer count/index and duration follow the constraints above. Success: `{"outcome":{...},"state":{...},"next_recommendations":[...]}`. Errors: `401` unauthorized; `400` invalid action; `409` no active subject; `422` invalid body/answers/duration.

```bash
curl -i -X POST "$BASE/api/interaction" -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"action":0,"answers":[0,1,0],"duration":8.5}'
```

### `GET /api/history?limit=20`

Access token required. `limit` is 1–200. Success: `{"history":[{"id":1,"topic":"...","resource_id":"...","resource_type":"quiz","difficulty":2,"duration":8.5,"score":66.7,"gain":0.1,"engagement":0.6,"timestamp":"..."}]}`. Errors: `401` unauthorized; `409` no active subject; `422` invalid limit.

```bash
curl -i "$BASE/api/history?limit=20" -H "Authorization: Bearer $TOKEN"
```

## Common error shape

FastAPI validation errors generally use `{"detail":[{"type":"...","loc":["body",...],"msg":"...","input":"..."}]}` with status `422`. Application errors use `{"detail":"..."}`. Authentication failures are normally `401`, authorization/enrollment failures `403`, missing objects `404`, duplicates/state conflicts `409`, rate limits `429`, and readiness failures `503`. Wrong HTTP methods return FastAPI `405`. Internal errors are not expected for valid requests; malformed input should be tested on the exact running version.
